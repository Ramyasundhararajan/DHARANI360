A

The automation engine itself

Nothing below works reliably until this exists. Today automation means a .bat file in Windows Task Scheduler on one PC — if that PC is off, nothing runs and nobody is told.

  1. A-01

    In-app job scheduler

    A scheduler that lives inside the application, not on somebody's desktop, running every timed job with a record of each run and an alert when one fails.

    Replaces send_digest.bat + backup.bat in Task Scheduler
    To buildPhase 1
  2. A-02

    Rules engine — "when this happens, do that"

    A rules table so a director can create an automation from a settings screen instead of a developer editing Python: pick a register, a condition, an action.

    Trigger record created / field changed / date reached → Action notify, create task, generate doc, escalate
    To buildPhase 1
  3. A-03

    One notification dispatcher

    A single place that knows how to reach a person — email, WhatsApp, SMS, in-portal bell, mobile push — so every automation just says "tell this person" and never re-implements sending.

    Extends mailer.py, adds WhatsApp Business API + in-app inbox
    Half-builtPhase 1
  4. A-04

    Message & document templates with merge fields

    Reusable templates in Arabic and English that pull real values from a record, so reminders and contracts stop being written by hand each time.

    Template + record → rendered email, WhatsApp or PDF
    To buildPhase 1
  5. A-05

    Escalation ladder

    Every automated request has an owner and a clock. Ignored for two days it goes to the manager, five days to the director — automatically, with the delay recorded.

    Unactioned N days → line manager → director → audit entry
    To buildPhase 2
B

Compliance, licensing & expiry

The strongest part of the portal today, and still one email a day to one address. An expiry should chase a named person until the new document is on file.

  1. B-01

    Daily red/amber compliance digest

    Already running: everything due or overdue inside the horizon, emailed each morning whether or not the portal is open.

    email_digest.py — configured on the Settings page
    RunningLive
  2. B-02

    Staged reminders, not one daily blob

    Each document type gets its own ladder — 90, 60, 30, 14, 7, 1 day and then daily once overdue — sent to the person who owns that document, not to one shared inbox.

    Expiry field → per-type reminder schedule → owner + manager
    Half-builtPhase 1
  3. B-03

    Renewal turns itself into a task

    An approaching expiry opens a renewal task with a checklist, an assignee and a due date, and closes only when the replacement document is uploaded and its new expiry read back into the register.

    90 days out → task → upload → new expiry → close loop
    To buildPhase 1
  4. B-04

    Trade licence, RERA & broker card calendars

    Statutory dates generated from issue dates rather than typed in — establishment card, immigration card, RERA broker cards per agent, Ejari, office tenancy, insurance.

    Issue date + document type → full renewal calendar
    To buildPhase 1
  5. B-05

    AML risk scoring on submission

    A KYC record scores itself Low / Medium / High from the answers given, and the score sets the re-screening interval — annual, six-monthly, quarterly — without anyone remembering to set it.

    Panel exists in insights.py; scoring + scheduling do not
    Half-builtPhase 2
  6. B-06

    Sanctions & PEP screening

    Every new client and beneficial owner screened against sanctions and PEP lists at onboarding and re-screened on schedule, with hits routed straight to the compliance officer.

    Client created → screening API → hit → escalation record
    To buildPhase 2
  7. B-07

    Retention clock on every record

    Records that pass their retention period are flagged for review and archived deliberately, instead of sitting forever or being deleted by guess.

    Closed date + retention rule → archive queue
    To buildPhase 2
  8. B-08

    One-click inspection pack

    A dated PDF bundle — licences, KYC files, transaction records, audit trail extract — assembled on demand for a regulator or auditor instead of assembled overnight by hand.

    Date range + scope → signed, page-numbered PDF pack
    To buildPhase 2
C

Documents — the actual paper-to-digital work

Attachments are stored today, but nothing is read out of them. This group is what turns a scan into data, and a data record back into a signed document.

  1. C-01

    OCR on upload — the form fills itself

    Emirates ID, passport, visa, trade licence, title deed: the scan is read, the name, number and expiry are extracted and offered back into the form for one-tap confirmation.

    Upload → OCR → suggested field values → human confirms
    To buildPhase 1
  2. C-02

    Documents generated from records

    Tenancy contracts, MOUs, listing agreements, NOCs, offer letters, commission invoices — produced from the register with correct numbering, never re-typed in Word.

    Record + template → numbered PDF, filed against the record
    To buildPhase 1
  3. C-03

    E-signature round trip

    Send for signature from inside the record, and let the signature come back on its own — status, signed copy and timestamp land in the register without anyone chasing a PDF by email.

    Send → signed → status + file written back automatically
    To buildPhase 1
  4. C-04

    Verification QR on every document

    Each generated document carries a QR that resolves to its record, so a printed page can be proven current rather than trusted.

    qrgen.py exists — extend it to generated documents
    Half-builtPhase 2
  5. C-05

    Versioning and supersession

    A replacement document supersedes the old one automatically: the previous version is locked, kept, and clearly marked, so nobody signs last year's copy.

    New upload → prior version archived + watermarked
    To buildPhase 2
  6. C-06

    Email intake

    A monitored mailbox that reads incoming attachments, works out which record they belong to, and files them — the end of "forward it to me and I'll upload it".

    Inbox → parse subject/sender/content → attach to record
    To buildPhase 2
  7. C-07

    WhatsApp document intake

    A client photographs their passport and sends it; it arrives in their KYC record with the sender matched. This is how documents actually reach a brokerage.

    WhatsApp media → matched by number → filed to client record
    To buildPhase 2
  8. C-08

    Completeness checks per record type

    Each record type knows which documents it must hold. Anything missing shows as a gap on the dashboard rather than being discovered at closing.

    Required-document list → live gap report
    To buildPhase 3

If you only build four things first

  1. A-01 and A-02 — the scheduler and the rules engine. Everything else is a rule on top of these. Without them each automation is another script on somebody's desktop.
  2. C-01 — OCR on upload. This is the single biggest reduction in typing, and it makes every expiry date in the system trustworthy because it came off the document.
  3. B-03 — renewals that become tasks. It turns the strongest feature you already have from a notification into a closed loop.
  4. D-01 to D-03 — lead capture, assignment and the response clock. The only group on this page that increases revenue rather than reducing risk.
